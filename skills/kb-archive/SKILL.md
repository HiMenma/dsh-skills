# 知识库归档（kb-archive）

## Overview

把一份文档按固定格式归档进个人知识库。目标是六个月后的自己和全文检索都能找到它，不用回忆当时的上下文。

本 skill 只管归档动作与文件头规范。正文保持原文档内容与结构，不改写、不重排、不删减。

## 何时启用

- 用户说"存到知识库""归档""保存到我的知识库"。
- 用户说"加 frontmatter""补索引"。
- 你已经产出一份长文档，用户表示要长期保留。

## 路径与命名

根目录：`${KB_ROOT:-$HOME/Documents/知识库}`

`KB_ROOT` 是环境变量，不写在仓库里。它没设置时，根目录是 `~/Documents/知识库`。要换目录，先 `export KB_ROOT=/你的/知识库`，下文命令不用改。下文所有路径都按 `${KB_ROOT:-$HOME/Documents/知识库}` 展开。

结构默认平铺。用户明确要求分组时才建子目录。

文件名规则：
- 用中文主题，可带一个限定词。例：`设计学习路线-后端工程师版.md`。
- 不加日期前缀。日期写在 frontmatter。
- 用连字符 `-` 分隔主题与限定词，不用空格。
- 禁用字符：`/` `:` `?` `*` `"` `<` `>` `|`。
- 扩展名固定 `.md`。

同名冲突处理：先读旧文件。确认是同一主题的更新才覆盖。不同主题就换文件名，不要覆盖。

## frontmatter 规范

六个字段，全部必填。缺一项就算归档未完成。

```yaml
---
title: 中文标题，不加书名号
date: 2026-11-09
source: https://原始链接，无出处填 none
type: 学习路线
tags: [设计, 审美, 学习路线]
status: 在用
---
```

字段取值：

| 字段 | 规则 |
|---|---|
| `title` | 与正文一级标题同义。不加书名号，不加日期。 |
| `date` | 正文定稿日，不是归档日。绝对日期，格式 `YYYY-MM-DD`。 |
| `source` | 原始 URL。多来源写第一个主来源。无出处填 `none`，不准留空。 |
| `type` | 六选一：`学习路线`、`研究`、`操作手册`、`会议纪要`、`决策记录`、`参考资料`。 |
| `tags` | 3 到 6 个。中文。方括号内逗号分隔。不加 `#` 前缀。 |
| `status` | 三选一：`初稿`、`在用`、`归档`。 |

## 正文结构

frontmatter 之后空一行，再写正文。正文一级标题用 `#`，且与 `title` 同义。

正文保留原文档内容与结构。归档不改写、不重排、不删减。原文的章节、段落、表格、引用、参考来源全部保留。若原文没有一级标题，只在正文最前面补一个与 `title` 同义的 `#` 标题，其他内容不动。

## 执行步骤

1. 确认目录存在。不存在就 `mkdir -p "${KB_ROOT:-$HOME/Documents/知识库}"`。
2. 读目标文件（如果已存在）。检查是否已有 frontmatter。有就改字段，不要叠加第二个 `---` 块。
3. 用 `bash` 写文件，不要用 `write` 工具。`write` 受工作区沙箱限制，写不到这个目录。
4. 写完后校验四件事：文件存在、字节数合理、前 10 行是 frontmatter 加一级标题、正文与原文一致（原文缺一级标题时，只允许补标题）。
5. 追加索引。见下一节。

推荐用 python heredoc 组装，避免 shell 转义把中文引号吃掉。

## 索引维护

索引文件：`${KB_ROOT:-$HOME/Documents/知识库}/_index.md`

表头固定：

```markdown
| 标题 | 类型 | 定稿日 | 标签 | 文件 |
|---|---|---|---|---|
```

新增一行，格式：

```markdown
| 标题 | 学习路线 | 2026-11-09 | 设计, 审美, 学习路线 | [文件名.md](文件名.md) |
```

只追加，不改既有行。同一文件已在表内时跳过，避免重复。

索引不存在就创建，标题为 `# 知识库索引`，正文第一句写明"本文件由归档流程维护"。

## 权限处理

目标路径在工作区外。`bash` 首次写入会被沙箱拒绝，报 `[sandbox: file access denied under workspace-write mode]`。

处理办法：用同一条命令重试，带 `sandbox_permissions: danger-full-access`。`justification` 用中文写明"归档到工作区外的知识库"。

不要改用别的方式绕开。不要先写工作区再复制，那是多余的一步。

## 自检清单

归档完成后逐条核对：

- [ ] 六个字段齐全，无空值，无重复 frontmatter 块。
- [ ] `date` 是定稿日，格式 `YYYY-MM-DD`。
- [ ] `tags` 三到六个，无 `#` 前缀。
- [ ] 正文一级标题与 `title` 同义。
- [ ] 正文保留原文档内容与结构，未重排、未删改（原文缺一级标题时，只补标题）。
- [ ] 文件名无禁用字符，无日期前缀。
- [ ] 文件可读，字节数大于 1 KB。
- [ ] `_index.md` 已追加一行，且无重复。

## 反例

```yaml
created: 今天              # 必须绝对日期
source:                    # 空值不合格，填 none
tags: #设计 #审美 #灵感     # 去掉 #，改成方括号列表
type: 文档                  # 必须落在六个取值里
```

其他反例：
- 文件名写 `2026-11-09-设计路线.md`。日期进 frontmatter，不进文件名。
- 每次归档新建 `设计路线-v2-final.md`。更新同一主题就覆盖原文件。
- frontmatter 写完整，正文一级标题却和 `title` 不一致。检索会命中两次。
- 把原文正文改写成摘要，或重排章节。归档保留原文，不改写结构。

## 与其他 skill 的关系

本 skill 只负责归档动作、frontmatter、文件名与索引。正文的写作规范不属于本 skill 的范围；归档时不改写正文。
